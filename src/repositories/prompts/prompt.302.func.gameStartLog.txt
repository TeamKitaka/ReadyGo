핵심요구사항) 게임 시작 로그 기능을 위한 Repository를 구현하고, 적용 결과를 체크리스트로 반환할 것.

            ❗ 전제 조건
                - 매칭/파티 등에서 실제 게임 시작 시점을 기록하는 로그 테이블이다.
                - 로그를 쌓는 형식이므로 INSERT와 SELECT만 필요하다.
                - game_start_logs 테이블을 사용할 것.
                - DB 스키마는 docs/database/04-table-details.md의 game_start_logs 정의를 따른다.

            1) Repository 기본 구조
                1-1) Supabase 클라이언트 사용
                    - src/lib/supabase/admin.ts의 supabaseAdmin을 사용할 것.
                    - import 경로: import { supabaseAdmin } from '@/lib/supabase/admin';
                
                1-2) 타입 정의
                    - database.types.ts의 Database 타입을 활용할 것.
                    - game_start_logs 테이블의 Row, Insert 타입을 활용할 것.
                    - 커스텀 타입이 필요한 경우 파일 내부에 정의할 것.

                1-3) 에러 처리
                    - 모든 함수는 error가 발생하면 throw error할 것.
                    - reviews.repository.ts의 패턴을 따를 것.
                
                1-4) 권한/RLS 전제 조건
                    - Repository는 supabaseAdmin(service role)을 사용하므로 RLS를 우회한다.
                    - 게임 시작 로그 생성 권한 검증은 호출부(API Route 또는 Hook)에서 선행되어야 한다.
                    - Repository 함수는 순수한 데이터 액세스 로직만 담당한다.

            2) 게임 시작 로그 조회 함수 (SELECT)
                2-1) getGameStartLogsByActor(actorId: string, limit: number = 50, offset: number = 0): Promise<GameStartLog[]>
                    - 특정 유저가 남긴 게임 시작 로그 목록을 조회할 것.
                    - game_start_logs 테이블 사용할 것.
                    - 조건:
                        - actor_id = actorId
                        - created_at 기준 내림차순 정렬 (최신 로그 우선)
                    - limit과 offset을 사용하여 페이지네이션 지원할 것.
                    - 반환 타입: database.types.ts의 game_start_logs.Row[] 타입 활용.

                2-2) getGameStartLogsByContext(contextType: string, contextId: string, limit: number = 50, offset: number = 0): Promise<GameStartLog[]>
                    - 특정 컨텍스트(match, party 등)에서 발생한 게임 시작 로그 목록을 조회할 것.
                    - game_start_logs 테이블 사용할 것.
                    - 조건:
                        - context_type = contextType
                        - context_id = contextId
                        - created_at 기준 내림차순 정렬 (최신 로그 우선)
                    - limit과 offset을 사용하여 페이지네이션 지원할 것.
                    - 반환 타입: database.types.ts의 game_start_logs.Row[] 타입 활용.

                2-3) getGameStartLogById(logId: number): Promise<GameStartLog | null>
                    - 특정 게임 시작 로그 ID로 단일 로그를 조회할 것.
                    - game_start_logs 테이블 사용할 것.
                    - 조건: id = logId
                    - 로그가 없으면 null을 반환할 것.
                    - 반환 타입: database.types.ts의 game_start_logs.Row | null 타입 활용.

            3) 게임 시작 로그 작성 함수 (INSERT)
                3-1) createGameStartLog(params: CreateGameStartLogParams): Promise<GameStartLog>
                    - 게임 시작 로그를 작성할 것.
                    - game_start_logs 테이블에 레코드 생성할 것.
                    - 파라미터 타입:
                        - actor_id: string (게임 시작을 요청한 유저)
                        - context_type: string (match, party 등 컨텍스트 타입)
                        - context_id: string (컨텍스트 식별자, 매칭 ID 또는 파티 ID)
                        - game_id?: string | null (선택 사항, Steam 게임 ID 등)
                        - game_name?: string | null (선택 사항, 게임명)
                    - insert 필드:
                        - actor_id: 전달받은 actor_id
                        - context_type: 전달받은 context_type
                        - context_id: 전달받은 context_id
                        - game_id: 전달받은 game_id (null 허용)
                        - game_name: 전달받은 game_name (null 허용)
                        - created_at: 현재 시간 (Supabase 자동 설정)
                    - 생성된 게임 시작 로그 정보를 반환할 것.
                    - 반환 타입: database.types.ts의 game_start_logs.Row 타입 활용.

            4) 타입 정의
                4-1) 커스텀 타입 정의
                    - GameStartLog: database.types.ts의 game_start_logs.Row 활용.
                    - CreateGameStartLogParams: 게임 시작 로그 작성 시 필요한 파라미터 타입
                        - actor_id: string
                        - context_type: string
                        - context_id: string
                        - game_id?: string | null
                        - game_name?: string | null

                4-2) 함수 파라미터 타입
                    - 모든 함수의 파라미터는 명시적 타입을 지정할 것.
                    - uuid 타입은 string으로 처리할 것.
                    - bigint 타입은 number로 처리할 것.

            5) 구현 주의사항
                5-1) Supabase 쿼리 패턴
                    - .from()으로 테이블 선택.
                    - .select()로 필요한 컬럼만 선택 (성능 최적화).
                    - .eq()로 필터링.
                    - .order()로 정렬.
                    - .limit(), .range()로 페이지네이션.
                    - .insert()로 생성.
                    - .single() 또는 .maybeSingle()로 단일 레코드 조회.

                5-2) 에러 처리
                    - 모든 Supabase 쿼리 결과에서 error 체크할 것.
                    - error가 존재하면 throw error할 것.
                    - try-catch는 호출하는 쪽(Hook 등)에서 처리할 것.

                5-3) 테이블 사용 규칙
                    - ✅ game_start_logs 테이블만 사용할 것.
                    - ✅ 로그를 쌓는 형식이므로 INSERT와 SELECT만 구현할 것.
