핵심요구사항) 다음 기능을 step-by-step으로 구현하고, 각 항목의 적용 여부를 체크리스트로 반환할 것.

0) 파일/Export 규칙
	- 파일 위치: src/repositories/matchResultsCache.repository.ts
	- named export만 사용 (default export 금지)
	- 함수명은 명확한 CRUD 동사 사용 (findByViewer, upsert, delete 등)

1) 타입 정의
	- CachedMatchResult 인터페이스 정의:
		- viewer_id: string
		- target_id: string
		- score: number
		- reasons: any (JSONB)
		- tags: any (JSONB)
		- computed_at: string
	- Database 타입 import: import type { Database } from '@/types/supabase'

2) findByViewer 함수
	- 함수명: findByViewer
	- 입력:
		- client: SupabaseClient<Database>
		- viewerId: string
		- targetIds: string[]
	- 동작:
		- match_results_cache 테이블에서 조회
		- viewer_id = viewerId AND target_id IN targetIds
		- 점수 내림차순 정렬 (score DESC)
	- 반환: Supabase 응답 그대로 ({ data, error })

3) upsert 함수
	- 함수명: upsert
	- 입력:
		- client: SupabaseClient<Database>
		- data: { viewer_id, target_id, score, reasons, tags }
	- 동작:
		- computed_at을 현재 시간으로 설정
		- onConflict: 'viewer_id,target_id' (PRIMARY KEY)
		- 중복 시 업데이트, 없으면 삽입
	- 반환: Supabase 응답 그대로

4) deleteByViewerAndTarget 함수
	- 함수명: deleteByViewerAndTarget
	- 입력:
		- client: SupabaseClient<Database>
		- viewerId: string
		- targetId: string
	- 동작:
		- viewer_id = viewerId AND target_id = targetId 삭제
	- 반환: Supabase 응답 그대로

5) deleteAllByViewer 함수
	- 함수명: deleteAllByViewer
	- 입력:
		- client: SupabaseClient<Database>
		- viewerId: string
	- 동작:
		- viewer_id = viewerId인 모든 레코드 삭제
	- 반환: Supabase 응답 그대로

6) 금지 사항
	- 비즈니스 로직 포함 ❌
	- 데이터 가공/변환 ❌
	- try-catch 남용 ❌ (Supabase 에러는 caller에게)
	- Domain 타입 의존 ❌
	- Service Layer 호출 ❌
	- UI/Hook 의존 ❌

7) Immutability 규칙
	- 입력 파라미터 직접 수정 ❌
	- 반환값은 Supabase 응답 그대로
