핵심요구사항) chat_room_members 테이블에서 같은 room_id를 가진 두 개의 user_id를 조회하는 Repository 함수를 구현하고, 적용 결과를 체크리스트로 반환할 것.

            ❗ 전제 조건
                - chat_room_members 테이블은 채팅방 참여자를 관리하는 테이블이다.
                - 같은 room_id를 가진 두 사용자를 조회하는 기능을 제공한다.
                - 1:1 채팅방에서 두 사용자 정보를 조회하는 용도로 사용된다.

            1) Repository 기본 구조
                1-1) Supabase 클라이언트 사용
                    - src/lib/supabase/admin.ts의 supabaseAdmin을 사용할 것.
                    - import 경로: import { supabaseAdmin } from '@/lib/supabase/admin';
                
                1-2) 타입 정의
                    - database.types.ts의 Database 타입을 활용할 것.
                    - chat_room_members의 Row 타입을 활용할 것.
                    - 커스텀 타입이 필요한 경우 파일 내부에 정의할 것.

                1-3) 에러 처리
                    - 모든 함수는 error가 발생하면 throw error할 것.
                    - partyMessages.repository.ts의 패턴을 따를 것.
                
                1-4) 권한/RLS 전제 조건
                    - Repository는 supabaseAdmin(service role)을 사용하므로 RLS를 우회한다.
                    - Repository 함수는 순수한 데이터 액세스 로직만 담당한다.

            2) 채팅방 멤버 조회 함수
                2-1) getChatRoomUserIds(roomId: number): Promise<string[]>
                    - 특정 채팅방(room_id)에 속한 모든 user_id를 조회할 것.
                    - chat_room_members 테이블 사용할 것.
                    - room_id로 필터링할 것.
                    - 조회할 필드:
                        - user_id: string | null - 참여 유저 ID
                    - room_id가 null이 아닌 레코드만 조회할 것.
                    - user_id가 null이 아닌 값만 필터링하여 반환할 것.
                    - 반환 타입: string[] (user_id 배열)
                    - 조회 결과가 없으면 빈 배열([])을 반환할 것.
                    - 참고: partyMessages.repository.ts의 getPartyMembers 함수 패턴을 따를 것.

            3) 타입 정의
                3-1) 커스텀 타입 정의
                    - ChatRoomMember: database.types.ts의 chat_room_members.Row 활용.

                3-2) 함수 파라미터 타입
                    - 모든 함수의 파라미터는 명시적 타입을 지정할 것.
                    - uuid 타입은 string으로 처리할 것.
                    - bigint 타입은 number로 처리할 것.

            4) 구현 주의사항
                4-1) Supabase 쿼리 패턴
                    - .from()으로 테이블 선택.
                    - .select()로 필요한 컬럼만 선택 (성능 최적화).
                    - .eq()로 room_id 필터링.
                    - .not('room_id', 'is', null)로 null 값 제외.
                    - .not('user_id', 'is', null)로 null 값 제외.

                4-2) 데이터 필터링
                    - room_id가 null이 아닌 레코드만 조회할 것.
                    - user_id가 null이 아닌 값만 반환 배열에 포함할 것.
                    - TypeScript 타입 가드를 사용하여 null 필터링할 것.
                    - 예: .filter((id): id is string => id !== null && id !== undefined)

                4-3) 에러 처리
                    - 모든 Supabase 쿼리 결과에서 error 체크할 것.
                    - error가 존재하면 throw error할 것.
                    - try-catch는 호출하는 쪽(Hook 등)에서 처리할 것.

                4-4) 반환 데이터 처리
                    - 조회 결과가 없으면 빈 배열([])을 반환할 것.
                    - user_id만 추출하여 string[] 형태로 반환할 것.
