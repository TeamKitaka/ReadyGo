            [문제점]
            - `processPendingMessageUpdates` 함수 내 정렬 로직에서 메시지가 없는 채팅방은 `0`을 사용하여 항상 맨 아래로 이동
            - 실시간 메시지 수신 시 정렬 로직에서도 메시지가 없는 채팅방은 `0`을 사용하여 항상 맨 아래로 이동
            - Repository 레벨에서는 `room.created_at`을 fallback으로 사용하지만, Hook 레벨에서는 사용하지 않음
            - 실시간 업데이트 시 정렬이 불안정함

            [해결 방안]
            - `processPendingMessageUpdates` 함수 내 정렬 로직에서 `0` 대신 `room.created_at`을 fallback으로 사용
            - 실시간 메시지 수신 시 정렬 로직에서도 `0` 대신 `room.created_at`을 fallback으로 사용
            - Repository와 일관성 유지
